# 番茄钟计时器 · 产品需求文档（PRD）

> V1.0 · 2026-11-17 · 来源：`需求调研.md` · 定位：**打开即计时、节奏自动化、数据看得见**的轻量番茄工作法工具

---

## 1. 产品概述与目标用户

**产品定位**：一款基于番茄工作法（25 分钟专注 + 5 分钟休息循环）的计时工具。核心是「精准计时 + 自动节奏 + 完成统计」——把专注与休息的循环交给工具，让用户只管专注。

**解决的问题**：手动计时易分心、忘记休息或休息过头；不清楚自己今天专注了多久、完成了几个番茄；不同场景下 25/5 的节奏不合适，需要自定义；时间到了没有可靠提醒。

**目标用户**：学生、职场个人、自由职业者、远程办公人群（16–45 岁），需要管理专注节奏，桌面与手机双端切换，不愿装重型软件。典型路径：设定时长 → 开始专注 → 到点提醒并自动进入休息 → 循环中积累番茄 → 查看统计复盘。

**产品目标**：开始/暂停/重置 ≤ 1 次点击；计时精准（误差 ≤ 1s，休眠/切后台不漂移）；到点必有提醒（声音或视觉至少其一）；MVP 无后端、断网可用；手机端能走通全流程。

**范围与假设**：V1.0 为纯前端单机版，数据存本地。原始需求未指定平台，推荐以 **Web / PWA**（可安装到桌面、离线可用）为交付形态；桌面/原生 App 作为后续可选路径（见 §5.2）。不做账号、云同步、多人协作、原生 App、第三方集成。

### 2.2 关键规则（先把口径定死）

1. **计入口径**：只有工作阶段自然倒计时到 0 才 `番茄数 +1`；手动跳过、重置、提前进入下一阶段均不计。
2. **计时基准**：以 `endTimestamp`（结束时间戳）为准，用 `Date.now()` 差值计算剩余时间；绝不用 `setInterval` 每秒递减（后台标签页会被节流而漂移）。
3. **阶段流转**：工作 → 短休；每 `长休间隔` 个工作阶段 → 长休；长休结束 → 回到工作，计数循环重置。
4. **状态边界**：计时器状态限定 `idle | running | paused | finished`，配合 `phase: work | shortBreak | longBreak`；禁止非法跳转（如 idle 直接 finish）。
5. **自动循环关闭时**：每阶段到点后停在 `finished` 等待用户手动开始，不自动推进。
6. **刷新/重开恢复**：依据持久化的 `endTimestamp` 与运行状态恢复；若离线期间已到点，按「完成一次」处理并补记统计（仅工作阶段）。
7. **本地存储优先**：数据仅存当前浏览器；存储不可用时降级为内存态并提示「数据仅存本机，清除浏览器数据会丢失」。
8. **时长输入**：数字或步进输入，逻辑层对越界值做 clamp（按下限/上限截断），拒绝非数字。

## 3. 功能优先级

| 版本 | 范围 |
| --- | --- |
| **V1.0 MVP（P0，必须）** | 功能 1–5、7–9、11–13、15–16、27 + 第 4 章界面规范 + 本地持久化。闭环为「设定 → 专注 → 提醒 → 休息 → 计数」 |
| **V1.1（P1，应该）** | 功能 3、6、10、14、17–20、22、24、26、28 + 设置/统计/任务界面完善 |
| **V2.0（P2，可以）** | 功能 21、23、25 + 音效库扩展、自定义主题 |
| **暂不做（P3，明确排除）** | 账号与云同步、多人协作/排行榜、原生移动 App、日历/第三方工具集成、白噪音 |

**MVP 明确不做**：长休息与自动循环（先用「工作 + 短休 + 手动」跑通核心闭环）；任何服务端能力；图表与任务管理；深色模式。

> 说明：番茄工作法完整闭环依赖长休息，若评审认为「无长休即不完整」，可将功能 3 提升入 P0；此处按最小可用闭环划分。

## 4. 界面设计

### 4.1 设计风格

简洁、克制、留白充足——打开即专注，不被干扰。视觉中心是巨型倒计时；靠颜色 + 字重 + 图标区分状态，不只靠文字；动效克制（150–250ms，仅用于状态反馈）。移动端不是桌面等比缩小，而是单列重排。

### 4.2 视觉规范

| 项目 | 规范 |
| --- | --- |
| 模式主色 | 专注 `#EF4444`（番茄红，Hover `#DC2626`）；短休 `#10B981`；长休 `#3B82F6`。当前模式决定主题色 |
| 背景 / 卡片 | 页面 `#F8FAFC`（暗色 `#0F172A`），卡片 `#FFFFFF`（暗色 `#1E293B`） |
| 文本 / 边框 | 主文本 `#1E293B`、次文本 `#64748B`、边框 `#E2E8F0` |
| 倒计时数字 | 字号 `96–128px`（移动端 `64px`），等宽数字字体（`tabular-nums`）防跳动 |
| 圆角 | 按钮/输入 `8px`，卡片/模态 `12px`，进度环用 SVG `stroke-linecap: round` |
| 阴影 | 卡片 `0 1px 2px rgba(15,23,42,.06)`；主按钮光晕 `0 4px 12px rgba(239,68,68,.28)` |
| 字体 / 间距 | 系统字体栈（无在线字体），14/16/20/32/96px；4px 基准网格（8/12/16/24/32） |
| 可访问性 | 正文对比度 ≥ 4.5:1、焦点环可见、图标按钮带名称、核心流程全键盘可达；遵循 `prefers-reduced-motion` |

### 4.3 页面结构

单页、视图切换（计时 / 统计 / 设置），桌面内容区 `720px` 居中。

**计时页（主界面）**
```
        [ 专注 | 短休 | 长休 ]         ← 模式标签，当前高亮
   今日 🍅 3 / 8       ●●○● / 4        ← 顶部信息条
            ╭─────────╮
            │  25:00  │              ← 巨型倒计时 + 环形进度
            ╰─────────╯
         [▶ 开始]  [↺ 重置] [⏭ 跳过]  ← 控制区
       当前任务：______________        ← 可点击编辑
```

**设置页**：分组表单——时长设置（数字+步进）、提醒设置（Toggle + 音效选择）、循环设置、每日目标、外观主题。即时生效，无「保存」按钮。

**统计页**：顶部四卡（今日番茄 / 本周番茄 / 累计专注 / 连续天数）+ 中部图表（7/30 天柱状图、周热力图）+ 底部历史记录列表。

### 4.4 组件与状态

- **阶段反馈**：进入休息时整体主色切换（红→绿→蓝），进度环有一次完成动画（填充 + 轻微缩放）。
- **临界提示**：最后 10 秒倒计时数字渐变变色；到点时环形进度完成动画 + 提醒触发。
- **控制按钮**：开始/暂停为实心主色按钮（高 48px、带光晕），重置/跳过为白底灰边次按钮；暂停时主按钮文字切为「继续」。
- **触控**：所有可点区域 ≥ 44×44px；移动端按钮横向均分、加大间距。
- **反馈**：操作结果用轻量 Toast（2–3s 自动消失）；统计数值切换用短过渡。

### 4.5 响应式设计

| 断点 | 要点 |
| --- | --- |
| `< 640px` | 单列；倒计时数字 `64px`；控制按钮横向铺满；统计卡 2×2；设置为底部抽屉；无横向滚动，适配安全区 |
| `640–1024px` | 单列，内容区 `560px`；顶部信息条两行 |
| `≥ 1024px` | 内容区 `720px` 居中；页签横向排列 |

## 5. 技术栈建议

### 5.1 推荐方案（Web / PWA）

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | **React 18 + TypeScript** | 生态成熟、单向数据流清晰，TS 锁死状态机与枚举 |
| 构建 | **Vite** | 启动快、HMR 好、配置简单 |
| 状态管理 | **Zustand**（含 `persist` 中间件） | 轻量、API 简洁，天然覆盖本地持久化与恢复 |
| 样式 | **Tailwind CSS** 或 CSS Modules | 快速构建一致 UI；主题色用 CSS 变量实现切换 |
| 计时核心 | 自定义 Hook `usePomodoroTimer` + 时间戳差 | 精准、可测、与 UI 解耦 |
| 通知 | **Web Notification API** | 原生系统通知，无需后端 |
| 提示音 | **Web Audio API** | 可编程生成提示音，零音频资源依赖（亦可换 mp3） |
| 图表（P2） | **Recharts** | 声明式、React 友好 |
| 图标 / 日期 | **lucide-react** / **date-fns** | 风格统一 / 日期比较可靠 |
| PWA | **vite-plugin-pwa** | 一键生成 Service Worker，支持安装与离线 |
| 测试 | **Vitest + React Testing Library** | 覆盖计时算法与状态转换 |
| 部署 | 静态托管（Vercel / Netlify / GitHub Pages / COS） | 纯静态产物，零运维 |

**选型理由**：需求核心是「精准计时 + 状态流转 + 派生统计 + 本地持久化」。React + TS 表达状态机最直接；Zustand `persist` 直接覆盖本地存储与恢复；时间戳方案解决后台漂移；产物纯静态、断网可用、零运维。V1 不引入 UI 组件库与后端。

**实现要点**：
- 计时用 `endTimestamp - Date.now()` 计算剩余，页面可见时用 `requestAnimationFrame`/定时器刷新视图，隐藏后返回自动校准。
- 统计与状态流转写成纯函数便于单测；番茄计数分母为 0 时返回 `0`。
- 日期统一用 `YYYY-MM-DD` 字符串比较（避开 `new Date('2026-11-17')` 的时区偏移问题）。
- 通知权限被拒绝走降级分支；存储读写 `try/catch` 并预留 `version` 字段便于迁移。
- 用户输入一律文本渲染，不拼 `innerHTML`；列表 key 用唯一 `id`。

### 5.2 备选平台路径（后续可选）

- **桌面应用**：Tauri（推荐，体积小）或 Electron —— 获得系统托盘、原生通知、开机自启。
- **移动应用**：React Native / Flutter —— 可复用业务类型与工具函数，但 UI 与发版独立。
- **建议**：先以 PWA 交付 MVP 验证需求，再评估是否封装为桌面/原生。

## 6. 代码风格与架构模式

### 6.1 代码风格（强制）

- **TypeScript strict**：禁用隐式 `any`；核心数据模型 `TimerState`、`Settings`、`SessionRecord`、`Phase` 必须有明确类型/枚举定义。
- **命名约定**：组件/类型 `PascalCase`（`TimerRing`、`TimerState`）；函数/变量 `camelCase`（`formatTime`、`remainingSeconds`）；常量 `UPPER_SNAKE_CASE`（`DEFAULT_WORK_MINUTES`）。
- **组件规范**：全部函数式组件 + Hooks，禁止类组件；单一职责，单文件不超过约 200 行。
- **工具配置**：ESLint + Prettier 统一格式（2 空格缩进、单引号、尾逗号），提交前自动格式化。
- **注释原则**：只在关键/复杂逻辑处注释（如时间戳补偿算法），命名即文档。
- **无硬编码**：时长、音效、目标等默认值统一收敛到 `constants.ts`。

### 6.2 架构模式

**分层架构（关注点分离）**

```
src/
├── components/     # 纯 UI 组件（TimerRing、ControlButtons、ModeTabs…）
├── pages/          # 页面容器（TimerPage、StatsPage、SettingsPage）
├── hooks/          # 自定义 Hooks（usePomodoroTimer 核心计时逻辑）
├── store/          # Zustand 状态（timerStore、settingsStore、statsStore）
├── services/       # 副作用封装（notification、audio、storage）
├── types/          # TypeScript 类型定义
├── constants/      # 默认配置常量
├── utils/          # 纯函数（时间格式化、日期计算、统计聚合）
├── App.tsx
└── main.tsx
```

**关键设计决策**
1. **计时逻辑与 UI 解耦**：核心计时封装在 `usePomodoroTimer`，UI 只消费状态，便于测试与复用。
2. **时间戳精准计时**：记录 `endTimestamp`，用 `Date.now()` 差值算剩余；不依赖 interval 递减。
3. **有限状态机 + 显式阶段**：`status: idle|running|paused|finished` × `phase: work|shortBreak|longBreak`，杜绝非法状态。
4. **副作用隔离**：通知、音效、存储统一放 `services/` 层，业务代码不直接调浏览器 API，便于 mock 与测试。
5. **持久化与迁移**：Zustand `persist` 落盘 localStorage，数据预留 `version` 字段，读写 `try/catch` 容错。

### 6.3 边界条件处理

| 场景 | 处理 |
| --- | --- |
| 页面刷新/关闭再打开 | 按持久化 `endTimestamp` 恢复；已到点按完成处理并补记统计 |
| 系统休眠/锁屏/切后台 | 唤醒后用时间戳差值校准，不产生累计误差 |
| 通知权限被拒绝 | 降级为页面内弹窗 + 标题闪烁（功能 15） |
| 时长输入非法（负数/非数字/超范围） | 输入层校验 + 逻辑层 clamp |
| 本地存储不可用（隐私模式） | 降级为内存存储并提示数据不保留 |
| 跳过/重置 | 不计入统计，仅重置阶段状态 |

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏 < 2s；计时界面长期运行无明显内存增长 |
| 精准度 | 计时误差 ≤ 1s，休眠/切后台后自动校准 |
| 可用性 | 核心操作键盘可达；按钮有清晰焦点态；支持主流浏览器 |
| 隐私 | 数据仅本地存储，不上传、不采集行为 |
| 兼容性 | 近两年 Chrome / Edge / Safari / Firefox；移动端 Safari 需验证通知兼容性 |
| 可维护性 | 模块边界清晰；计时算法与状态转换有单测覆盖 |

## 8. 验收标准（MVP / P0）

- [ ] 默认显示 25:00 专注倒计时，可开始、暂停、继续、重置、跳过。
- [ ] 切标签页/锁屏 5 分钟后再返回，剩余时间准确（误差 ≤ 1s）。
- [ ] 可自定义工作与休息时长，刷新后设置仍生效。
- [ ] 工作阶段结束触发提示音 + 系统通知；拒绝通知权限时有页面内降级提示。
- [ ] 完整完成一个工作阶段后，番茄数 +1 且可在统计中查看；跳过/重置不计。
- [ ] 桌面与移动端浏览器布局正常、按钮可用。
